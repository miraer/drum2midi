# Core pipeline. Versions are the ones this was developed and measured against;
# newer ones generally work, with the torchaudio caveat noted below.
#
# Python 3.10 - 3.13, and the ceiling is not ours. audio-separator depends on a
# compiled package whose name depends on the platform, per its own metadata:
#   Windows       diffq-fixed  wheels for cp310-cp313; on 3.14 pip falls back to the
#                              sdist and the build fails
#   Linux, macOS  diffq        wheels up to cp310 only; above that pip compiles it,
#                              which needs a C compiler (build-essential and
#                              python3-dev on Debian/Ubuntu, Xcode's command line
#                              tools on macOS)
# Both say `requires_python: >=3.7.0`, which is why a failure arrives as a compiler
# error deep in a dependency rather than as a version check. 3.12 is the safest
# everywhere and is what CI uses.
#
# Only extracting drums from a whole song (--from-song, htdemucs) imports diffq; the
# default MDX23C separator does not. So on macOS, where no wheel exists and a compiler
# is often missing, it is optional: audio-separator is left out of this file there,
# and setup_env.py installs it and its other dependencies itself, then tries diffq
# and carries on without it. Use setup_env.py on macOS rather than this file alone.
#
# Install torch first if you want a specific build. The plain `pip install torch`
# wheel on Windows has NO CUDA, so an NVIDIA card sits idle and everything runs on
# the CPU without saying why -- `.venv\Scripts\python.exe devices.py` reports that
# when it happens.
#
# Run these through the virtualenv's own interpreter, not a bare `pip` or `pip3`.
# pytorch.org gives the command as `pip3 install torch ...`, and on Windows a bare
# pip3 is usually the system Python: the CUDA wheel then installs perfectly into an
# interpreter this project never uses, and the only sign is that torch here still
# says `+cpu`. `<interpreter> -m pip` cannot miss in that way.
#   NVIDIA:  .venv\Scripts\python.exe -m pip install torch --index-url <from pytorch.org>
#   CPU:     .venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
#   Intel:   .venv\Scripts\python.exe setup_env.py --with-intel-gpu
# No CUDA version is named here on purpose. The index carries cu118 through cu134 and
# the right one depends on the driver; an earlier version of this comment hard-coded
# cu124, which was already three releases stale on the day it was written. The part
# worth copying from pytorch.org is the index URL; the interpreter is ours.
#
# ADTOF-pytorch is not on PyPI and must be installed from git:
#   git clone --depth 1 https://github.com/xavriley/ADTOF-pytorch.git
#   .venv\Scripts\python.exe -m pip install -e ./ADTOF-pytorch

# Separation. audio-separator pulls the MDX23C drum model on first use and also
# mirrors htdemucs, which matters where dl.fbaipublicfiles.com is unreachable.
#
# audio-separator also needs FFMPEG, which is a program rather than a package and so
# cannot be listed here. It runs `ffmpeg -version` on startup and dies without it.
# Nothing in this project imports ffmpeg, which is why it went undocumented until it
# broke a conversion:
#   Windows:  winget install Gyan.FFmpeg    (then a new terminal, for PATH)
#   macOS:    brew install ffmpeg
#   Linux:    sudo apt install ffmpeg
